# ADR-002：可记忆空间名称与一步短分享

Status: Accepted  
Date: 2026-10-29

## 背景

用户验收认为UUID路径加两份长凭证不利于传播，且分享需要“打开面板→生成→复制”过多操作。用户要求自定义/默认随机空间名称，并安排并行开发。当前UI阅读基线已由用户调整验收，不能借机回退。

## 决策

名称是定位入口而非权限；新建/name#o=seed，用单个32字节随机seed通过不同HKDF域导出owner凭证及正文密钥，保持原管理安全强度。默认只读/name#r=seed使用16字节随机能力，通过独立HKDF域得到鉴权和包装密钥。正文密钥包装密文保存在服务端，seed仍只在fragment，服务端无法解密。只读分享具128bit随机访问能力，不是短数字口令；正文仍采用AES-256-GCM。

分享面板一步准备并复制，链接和二维码即达。重复分享复用server descriptor；owner通过正文密钥解开ownerEnvelope恢复原seed，刷新或换设备不丢失同一分享。明确“更新链接”才轮换，撤销覆盖新旧读者。高级设置折叠。

保留v1独立key/token、密码链接、UUID API、旧数据库。新增name及compact_shares表，增量迁移而不重加密用户数据，原owner凭证不改变。已有空间首次分享可补名称，新grant和旧reader并存；明确更新/撤销才使旧分享失效。实现细节见docs/SHORT-LINKS.md。

## 考虑的替代方案

- 名称即公开访问：短但会降低已确认隐私边界，不采用。
- 普通短链把完整密钥存服务端后重定向：便捷但破坏数据库无法解密正文的承诺，不采用。
- 只压缩UUID：不能消除URL里两份长随机值，改善有限。
- 账户或短数字配对码：引入登录/防猜测/配对状态机，超出本轮范围。

## 影响

名称作为公开元数据，不应使用私密信息；名称不能作为授权。管理与只读完整链接仍是访问能力，泄露者拥有相应权限。密码模式可更长，作为高级选项明确。旧管理链接不强行缩短，兼容性优先；新分享可短链接化。默认只读分享不保证收回已被复制的内容。
