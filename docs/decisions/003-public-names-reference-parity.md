# ADR-003：新建空间按名称访问，与旧private并存

状态：已批准，2026-10-29。

用户在实际验收后认为命名与分享仍不够方便，明确要求先按Jian.la的全部功能、交互和风格对齐。架构负责人说明“名称可读写”会改变默认私密边界后，用户明确选择“完全照参考站：凭名称即可查看和修改，密码可选”。

因此新建前端空间显式指定public，使用/name和/name?readonly，默认永久。readonly是页面模式，无法作为权限隔离承诺；设置空间密码才能限制知道名称者的访问。public正文密钥保存在服务端，与浏览器加密envelope兼容，但不能宣称public端到端私密。密码仅保存scrypt哈希和盐，解锁会话在服务端内存，HttpOnly Strict cookie分空间。

旧客户端省略accessMode仍创建private；旧数据迁移默认private，旧密文、密钥、凭证与能力链接均保留。private读写角色仍由服务端鉴权，不会因名称或public接口绕过。模式不可通过PATCH改变。

视觉采用参考站的长首页、横向页签与右栏二维码/信息，替代旧侧栏工作台。用户已批准的16px正文/14px控件阅读底线继续适用；不照搬小字号、错误默认值、第三方收款码或身份。

完整API与逐项对照见[JIANLA-PARITY.md](../JIANLA-PARITY.md)。门禁包括旧schema迁移、权限隔离、密码会话、统计不续期、排序主页面保护、浏览器功能、可访问性与实际截图审查。只在本地Docker验收，不授权公网发布。
