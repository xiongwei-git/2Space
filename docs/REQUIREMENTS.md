# 2Space 1.0 需求基线

2026-10-29：用户明确授权开始架构和并行开发。本文件将已确认内容与工程默认选择分开。

## 用户确认

- 代码仓库 git@github.com:xiongwei-git/2Space.git。
- 本地调试，Docker开发和部署，不执行公网部署。
- 编辑器轻量，支持粘贴富文本格式，不能做成笨重文档套件。
- 文本包含代码格式。图片二期；任意小文件不提供。
- 安全和隐私是核心卖点，不以可猜测名称充当授权。
- 多任务同时实施，由架构负责人统一契约和验收。

## 1.0实现基线（工程默认）

- 品牌以2Space为准，“两格”为候选中文名，不擅自定为正式注册名称。
- 匿名创建私有空间，随机ID/管理凭证；保存管理链接用于另一设备进入，凭证丢失无法找回。
- 最多6份笔记，标题、内容、代码语言均加密；默认24小时，最短30分钟、最长30天，读取不续期，内容写入续期。
- 粘贴保留段落、标题、粗斜体、下划线、列表、链接、引用、简单表格、代码。去掉字体/颜色/背景/页面布局/图片/危险HTML。
- 代码支持语言选择/语法高亮/保持缩进/复制原文，不执行代码；不默认自动格式化。
- 自动保存、可见状态、断网草稿、冲突保留，SSE通知接收端拉取新版本。
- 复制富文本、复制纯文本、下载TXT；复制失败提示手动选择。
- 只读链接和二维码，独立服务端只读令牌，可轮换和撤销。分享含整个空间（界面明确提示），不是单页假隔离。
- 可选密码封装链接（若本轮实现与验收完成才列为已交付）。密码只加密链接中的正文密钥，不代替服务端权限，也不是防止已持有原管理链接者访问。
- 主动删除空间/笔记需要界面确认；服务端幂等删除，至少保留一页。
- 图片与文件粘贴明确提示暂不支持，不偷偷上传或读取第三方图片。

## 轻量边界

- 初始壳与编辑器分包加载，无远程字体、分析脚本、广告、编辑器收费云依赖。
- 仅选择需要的Tiptap扩展和语法语言；包体实测记录，首次超出预算以构建结果分析，不盲目添加依赖。
- 默认静态资源gzip后目标：初始JS <150KB、编辑器分块 <350KB（目标而非未验证承诺）。

## 安全验收

管理/读者权限、取消readonly参数不提权、撤销立即拒绝新读取及断开旧流、AES往返与篡改拒绝、加密本地草稿、XSS和外部图片清理、revision冲突、到期删除、body限额与限速。
正文密文不意味着元数据隐身，也不能抵御被替换的前端JavaScript。上线前仍需独立审查、TLS、备份/清理流程及公开运营边界确认。

## 延后

账户、设备自动配对/短码、永久空间、全文服务器搜索、图片、文件、AI、多人字符级协同、系统剪贴板监听。1.0采用分享链接/二维码进入，避免短码加入独立猜测风险与配对状态机。
