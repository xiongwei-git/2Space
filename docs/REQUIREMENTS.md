# 2Space 1.0 需求基线

> 当前增量基线：2026-10-29用户明确选择新建空间凭名称查看和修改、密码可选。新public默认永久，`?readonly`仅页面模式；旧private空间和旧链接保持原权限与加密边界。最新需求、API和验收范围见[JIANLA-PARITY.md](JIANLA-PARITY.md)；历史命名短分享设计保留在SHORT-LINKS.md和ADR中。

2026-10-29：用户明确授权开始架构和并行开发。本文件将已确认内容与工程默认选择分开。

## 用户确认

- 代码仓库 git@github.com:xiongwei-git/2Space.git。
- 本地调试，Docker开发和部署，不执行公网部署。
- 编辑器轻量，支持粘贴富文本格式，不能做成笨重文档套件。
- 文本包含代码格式。图片二期；任意小文件不提供。
- 安全和隐私重要；用户最新明确批准新空间凭名称读写、密码可选，旧private保留独立权限。
- 多任务同时实施，由架构负责人统一契约和验收。

## 当前实现基线

- 品牌以2Space为准，“两格”为候选中文名，不擅自定为正式注册名称。
- 新建public匿名空间，首页自填名称或随机4位体验；直接/name进入，可选整空间密码。?readonly仅为查看模式。旧private UUID/短能力/密码链接继续有效。
- 最多6份笔记；主剪贴板固定第一不可删除，其他页可命名、排序和删除。新public默认永久，保留期限共13档；旧private原期限不变。读取不续期，内容写入续期。
- 粘贴保留段落、标题、粗斜体、下划线、列表、链接、引用、代码。表格粘贴转为行列文字，旧表格文字必须完整保留，载入不触发保存。去掉字体/颜色/背景/页面布局/图片/危险HTML。
- 代码支持语言选择/语法高亮/保持缩进/复制原文，不执行代码；不默认自动格式化。
- 自动保存、可见状态、断网草稿、冲突保留，SSE通知接收端拉取新版本。
- 复制富文本、复制纯文本、下载TXT；复制失败提示手动选择。
- public按参考顶部系统分享或复制当前可编辑地址，右栏可编辑/仅查看链接和二维码常驻。旧private顶部默认分享真正reader短链接并稳定复用，可更新或撤销。分享整个空间。
- 整空间访问密码、3分钟无操作+5秒锁定、访问统计、TXT下载、600ms/失焦/CmdS保存；旧private包装密码链接仍兼容。
- 主动删除空间/笔记需要界面确认；主剪贴板不可删除。
- 图片与文件粘贴明确提示暂不支持，不偷偷上传或读取第三方图片。

## 轻量边界

- 初始壳与编辑器分包加载，无远程字体、分析脚本、广告、编辑器收费云依赖。
- 仅选择需要的Tiptap扩展和语法语言；包体实测记录，首次超出预算以构建结果分析，不盲目添加依赖。
- 默认静态资源gzip后目标：初始JS <150KB、编辑器分块 <350KB（目标而非未验证承诺）。

## 安全验收

旧private管理/读者权限、取消readonly参数不提权；public名称读写/密码门禁与查看模式、撤销立即拒绝新读取及断开旧流、AES往返与篡改拒绝、加密本地草稿、XSS和外部图片清理、revision冲突、到期删除、body限额与限速。
正文密文不意味着元数据隐身，也不能抵御被替换的前端JavaScript。上线前仍需独立审查、TLS、备份/清理流程及公开运营边界确认。

## 延后

账户、设备自动配对/短码、全文服务器搜索、图片、文件、AI、多人字符级协同、系统剪贴板监听。1.0采用分享链接/二维码进入，避免短码加入独立猜测风险与配对状态机。
