# 安全与隐私规范

> 当前增量基线：2026-10-29用户明确选择新建空间凭名称查看和修改、密码可选。新public默认永久，`?readonly`仅页面模式；旧private空间和旧链接保持原权限与加密边界。最新需求、API和验收范围见[JIANLA-PARITY.md](JIANLA-PARITY.md)；历史命名短分享设计保留在SHORT-LINKS.md和ADR中。

## 产品保证与限制

正常客户端将标题、富文本、纯文本与代码语言以AES-256-GCM处理，再传到API，每次随机12字节IV。必须区分两种模式：

- 新public：用户已批准凭名称读写、密码可选。publicKey保存在服务端；只有通过空间密码门禁后才返回。服务器能还原public正文，不提供数据库泄漏下的端到端私密保证。`?readonly`只是页面模式。
- 旧private：正文密钥只在浏览器，链接fragment携带HKDF派生种子或旧独立key/token。数据库仅持有token哈希与分享envelope，不能仅凭数据库还原private正文。不同读写角色由服务端验证。

名称和时间、版本、大小等是元数据，不应包含秘密。模式不能通过PATCH转换，旧数据迁移保持private。

服务端向浏览器分发JavaScript，不能抵御被篡改的前端、恶意浏览器扩展或受感染设备；没有独立密码学审计，不宣称绝对安全或防恶意服务端。API校验密文信封结构，不具备在无密钥情况下证明所有提交都由AES产生的能力。

## 凭证

- private的空间ID和名称仅定位，访问在服务端验证Bearer。v1使用独立32字节随机token；新owner由32字节随机seed派生正文key和auth，新reader由16字节随机seed派生wrappingKey和auth，不同HKDF域隔离。短reader能力有128bit随机穷举门槛，不能当作低熵口令。数据库只存token哈希、keyEnvelope和ownerEnvelope，不能恢复seed或正文key。
- 前端不得将管理token写localStorage、请求查询参数或日志。浏览器历史和剪贴板仍可能包含完整能力链接，请用户保管。
- 默认分享原子create-or-get并复用已有descriptor，不导致旧链接失效；明确更新或撤销才关闭旧reader流并失效。旧v1分享与新compact分享兼容并存，显式更新清除旧v1读者。private去掉/修改URL显示参数不提权；public更换readonly显示模式可以打开编辑页，不能混淆。
- 共享整个空间，必须明确提示；不可把单页UI选中状态描述为单页访问授权。
- 旧private密码链接仅通过PBKDF2-SHA256（600000次）派生AES密钥，封装链接里的正文密钥。原管理链接仍然有效，不是账户密码变更。丢失密钥不能通过服务端重置找回。

## 整个空间的访问密码

public/private均可设置整个空间的访问密码；private仍需原Bearer。仅存scrypt哈希和独立盐，不存原密码。解锁发HttpOnly、SameSite=Strict、分空间cookie；内存会话最多30分钟，private绑定tokenHash。更改密码使旧会话和SSE失效，锁定使本次会话失效。错误解锁和设置密码有限速。重启需重新解锁。

前端3分钟无操作提示，再5秒锁定；锁定先写不含秘密的sessionStorage标记，防止离线锁请求失败后刷新直接打开。成功输入密码才清标记。密码忘记没有找回功能，已复制内容无法收回。部署cookie策略和已知角色cookie争用见OPERATIONS.md。

## 内容边界

富文本以允许的结构保留，删除脚本、iframe、表单、事件属性、CSS、任意class和图片。外部图片不能触发跟踪请求。纯文本和代码不执行，不自动格式化；仅安全URL协议可作为链接。

正文信封按解码密文字节限400000，最多6页；请求体有额外上限，API输入严格校验。版本号原子CAS，409保留两份，不能静默重写。断网草稿在本机同样加密，提交确认后清除。

## 生命周期

新public默认永久；旧private省略时仍默认24小时。支持永久与30分钟至3年的12档期限；访问、访问统计、排序、密码设置不续期，正文写入续期。修改保留期限从最后正文更新时间起算，可导致立即过期，UI须确认。到期先拒绝访问，再由清理任务删除活动数据库记录。SQLite启用secure_delete，但WAL、文件系统快照、备份及客户端副本可能残留密文；不承诺物理立即擦除。

主动删除需要界面确认，无回收站。主剪贴板不可删除，用户可删除整个空间。只读撤销不能收回已复制、截图或下载的内容。匿名空间没有服务端找回渠道。

## 部署

当前只本地loopback。Docker非root、根文件系统只读、数据目录700、命名卷持久化、安全响应头、无第三方统计/字体/脚本。公网必须TLS，且应补充备份保留/滥用处理/容量监控/限速与反向代理真实IP策略后单独验收，不从本地通过推断公网已可运营。

## 报告问题

不要在公开Issue贴能力链接、密钥、密码、正文、数据库或请求Authorization。使用合成数据、去敏路径和最小复现。依赖审计应结合可达路径与修复版本；禁止为消除提示直接npm audit fix --force。
