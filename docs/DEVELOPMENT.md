# 2Space 1.0 开发规范

## 目标

品牌2Space；口号“这边复制，那边就有。”。工具优先，轻量富文本粘贴保格式、代码保缩进、跨端同步、密码可选。
1.0支持最多6份文本笔记、自动保存、代码高亮、富文本/纯文本复制、TXT下载、二维码分享、真正只读与撤销、临时保留、加密正文、本地草稿恢复。图片二期，不提供任意文件、账户、AI、CRDT。
新public名称1–64位字母/数字/下划线/中划线，按名称可读写，密码可选；旧private仍使用独立能力授权。旧随机ID链接保持兼容。命名与一步分享规范见docs/SHORT-LINKS.md。

## 架构

单仓npm workspaces：apps/web(React/Vite/Tiptap)、apps/server(Fastify/SQLite)、packages/shared(纯类型与常量)。浏览器AES-GCM处理正文；旧private密钥只在浏览器，新public密钥按用户授权由服务端保存并受可选密码门禁保护。单实例SQLite+SSE，Docker volume持久化。生产扩容不是1.0目标。
Tiptap按需加载；只安装所需节点，不引入完整文档套件。保留段落、常用富文本粘贴与代码；可见工具精简，代码入口明确。表格转行列文字，不提供表格创建或表格依赖。粘贴去脚本、样式、图片、跟踪和危险URL。

## 验收与门禁

TypeScript strict；依赖精确锁在package-lock。单元/集成围绕权限、输入、加密、冲突、到期与清理；本地浏览器验证创建、富文本、双页同步、只读、撤销、手机布局。Docker构建运行后验证health与持久化。未验证项目必须明确列出。
默认绑定本机回环地址。跨设备自托管见 [自托管指南](SELF-HOSTING.md)。
日志不含正文、令牌、密码或完整URL；referrer-policy no-referrer、CSP、安全响应头。浏览器片段持有密钥，JS供应链/终端被攻破仍有风险。

## 视觉方向

工作台优先，双空间符号作为品牌点。色板：纸白#FFFFFF、浅雾#F3F6FA、墨蓝#18253B、主蓝#3159DB、边线#DEE5F0、成功绿#28755D。中文PingFang SC/系统无衬线，代码SFMono/Consolas。当前采用ADR-005的自主布局：首页左右分栏，名称入口与双设备内容示例并列；工作区1180px内主编辑画布+280px工具栏，900px以下自然单列。选区工具或精简工具条，避免Word菜单与宣传卡片墙。真实安全能力用简明状态和详情说明，不把加密参数摆在主流程。
当前布局以本节为准。字体不拉远程资源。

## Web阅读基线（web-reading-v1，2026-10-29批准）

本仓库维护字阶及自动验收阈值。欢迎页负责首次创建和说明；进入空间后以编辑任务为主，两者共用相同字阶。

写CSS前引用以下Type Scale并自审：正文/代码16px，控件/次要正文14px，明确元信息12px；标题不得通过压低解释文字形成对比。所有值按默认根字号16px描述，用rem及无单位行高实现；不固定用户根字号。

| 角色                       | Token                     | 默认值/行高      | 字重/使用                                                    |
| -------------------------- | ------------------------- | ---------------- | ------------------------------------------------------------ |
| 正文、代码                 | body                      | 16px / 1.75      | 400；编辑正文、预览正文、弹窗业务说明                        |
| 控件、次要正文、关键短提示 | secondary                 | 14px / 1.5–1.75  | 400–600；按钮、标签、保存/连接状态、到期规则、安全和风险提醒 |
| 辅助元信息                 | meta                      | 12px / 1.75      | 400；仅下列清单                                              |
| 首页导语                   | lead                      | 18px / 1.75      | 400                                                          |
| 区域标题                   | heading                   | 20px / 1.4–1.75  | 600                                                          |
| 文档/弹窗标题              | title                     | 24px / 1.35–1.75 | 600                                                          |
| 展示标题                   | display / display-compact | 32–48px / 1.35   | 600；窄屏32px                                                |

12px白名单只有：`.sidebar-heading > span`（笔记数量）、`.page-number`（笔记序号）、`.character-count`（字符计数）、`.site-footer .version`、`.home-footer .version`、`.board-footer .version`（版本号）。笔记摘要、权限、到期、连接与保存状态、删除风险不在清单。没有其他字号例外。笔记列表标题/摘要允许省略号，完整标题在文档标题输入框、正文在编辑区可读；代码保留缩进，允许局部横向滚动且可键盘聚焦。

唯一字号与字体值来源是 `apps/web/src/tokens.css`，组件样式在style.css引用语义Token。颜色使用主文字、次要文字、成功、危险、警告、动作等角色；次要文字仍须4.5:1。背景、边线与品牌风格保留。用户富文本的语义结构不改写；自动样式检查使用合成内容，不能据此声称所有用户内容均已验证。

## 阅读验收命令与证据

首次运行：`npm ci`，`npx playwright install chromium`。Linux CI使用 `npx playwright install --with-deps chromium`。浏览器与axe是开发依赖，不进入生产运行包。

- `npm run design:check`：静态检查字号Token、16/14/12基准、禁止字号!important与禁用缩放，并执行受控界面文案检查。
- `npm run test:parity`：随机端口和临时库验证public/private、密码、永久/13档、排序与统计，不操作3210。
- `npm run test:visual`：静态检查、构建、隔离本地服务、实际计算样式/字号/行高/字重/溢出检查、axe WCAG A/AA规则扫描及截图采集。服务监听随机loopback端口、临时数据库，不操作3210生产容器或现有笔记；结束关闭浏览器和服务并清理临时数据库。
- 脚本覆盖1280/390/320px的欢迎页、工作台、安全/分享/打开弹窗；桌面200%根字体及文字间距覆盖；桌面/手机只读、离线保存失败、冲突；手机不可用空间。离线为浏览器断网，冲突由合成409响应触发真实客户端处理；不可用空间由真实404触发同一过期/撤销提示，不冒称自然到期。
- axe扫描包括文字对比度等可自动判断项，失败阻止CI通过；没有整页禁用规则。需要人工判断的axe incomplete结果也写入报告供审查，不能据自动零违规宣称全站WCAG AA合规。
- 输出 `output/design-acceptance/*.png` 与脱敏 `report.json`；目录已被Git忽略。CI保留7天合成截图和报告，不录制trace/视频/DOM、请求或能力链接；分享链接和二维码遮罩。每次必须实际看图，检查中文层级、风险权重、裁切及响应式，记录所看文件与结论。
- 自动文字200%用根字体覆盖，320px检查1280/400%等效重排；它们不等于原生浏览器缩放。视觉交付还须原生浏览器200%/400%、键盘焦点与操作人工检查，并在验收记录中区分结果与未测项。

截图采集是审查证据，不是像素差异基准。本试点不提交自动生成截图，避免跨OS字体差异产生误报；后续如需像素回归，应固定OS/字体/浏览器，人工批准基准及更新。禁止靠改基准或增加宽泛豁免让失败转绿。

当前自主布局沿用自然页面滚动，替代此前100dvh内部滚动结构；宽度、文字、焦点与截图门禁继续保留。浏览器脚本还覆盖1355×1344、1280×900、1024×768的真实创建提示+空白/长文，不能只检查横向溢出；禁止通过缩小字号修复高度问题。

## 名称空间浏览器密码保护

当前增量以ADR-006、API v3和shared类型为准：普通public名称空间保持便捷访问；新版界面设置/更换密码时，浏览器派生独立正文key/proof、全空间原子重加密，服务器删除active正文key，仅存proof校验与KDF参数。取消密码明确确认后换新key回普通public。旧private链接、旧public密码门禁继续兼容，旧空间需通过新版设置新密码升级，不自动重写现有记录。

`npm run test:protection`构建后执行75项隔离浏览器密码保护门禁；CI直接在既有build后运行新脚本。覆盖独立Node解密、原密码/key不上传或持久化、跨浏览器context、修改/取消、旧空间升级、丢响应确认、旧密码草稿本机恢复、另一标签页晚写草稿保护。普通草稿按本页写入值核对后清理，无法用当前key打开的旧稿先独立保留，成功另存才删副本。避免并发构建同一 dist 目录。

新密码至少8字符，建议较长且不重复；明示忘记后无法恢复。密钥代际不匹配阻止旧写并重新验证。KDF只使用固定Web Crypto PBKDF2/HKDF/AES，不引入大型密码套件或编辑器依赖。无独立审计、真实HTTPS/实体设备验证时不得扩大安全承诺。
